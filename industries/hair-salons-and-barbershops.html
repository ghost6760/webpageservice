What the code prevents in a salon

The model understands and converses; the critical rules are enforced by code (the guardrails), whatever the conversation says. The ones that matter most here:

It does not confirm a taken slot. It looks for a gap that fits the whole service, not just the start time.

It does not double-book. Even if the client repeats the request or sends the day and time separately.

It does not invent a price. If a service has no price on your list, it does not make one up: it says it will be confirmed at the salon.

With an average ticket of $45 and a 70% contribution margin (an example assumption), the Pay-per-booking plan pays for itself with 3 saved appointments a month, already counting the $5 charged per booking. We count margin, not revenue: an appointment is not all profit.

Frequently asked questions

Does it know how long each service takes?

Yes: each service is set up with its length, and the assistant only offers slots where it fits in full.

Can clients choose their stylist?

Yes. With several stylists, each one has a calendar and clients can ask for theirs.

Does it pay off with low tickets?

That is what the Pay-per-booking plan is for: a small base fee and a fixed amount per booking, with a monthly cap so you never pay more than a fixed plan.

Does it work for walk-in only shops?

If everything is first come, first served, there is no calendar to fill and it would add little: it would answer hours and prices. It fits when you take appointments.
